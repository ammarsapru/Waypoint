FIRST-TIME SETUP (run once)
---------------------------

# Create the Python virtual environment and install backend dependencies.
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

# Install frontend dependencies.
Set-Location frontend
npm.cmd install
Set-Location ..

# Create the backend-only environment file, then edit .env and add your key.
Copy-Item .env.example .env

# Primary provider for model-backed Ask, Onboarding, mastery, missions, and issue investigation:

# Claude Code subscription fallback (enabled by default):

# WAYPOINT_PROVIDER_STARTUP_PROBE=1

# GITHUB_TOKEN=your_token_here

# Optional location for persisted chat and analysis-session state:
# WAYPOINT_STATE_PATH=.waypoint-data/waypoint.sqlite3


START THE APPLICATION FOR DEVELOPMENT
-------------------------------------

Open PowerShell terminal 1 in the project root and start the backend:

.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload

Open PowerShell terminal 2 in the project root and start the frontend:

Set-Location frontend
npm.cmd run dev

Then open the UI in a browser:
http://127.0.0.1:5173

Backend API documentation:
http://127.0.0.1:8000/docs

The backend reads .env from the project root when it starts. Restart the backend
after changing the key. The key must never be placed in frontend/.env or use VITE_.


OPTIONAL: START THE BACKEND WITH EXTENSIVE DIAGNOSTIC LOGS
----------------------------------------------------------

Run these commands in backend terminal 1 before the Uvicorn command:

$env:ONBOARD_LOG_LEVEL="DEBUG"
$env:ONBOARD_TRACE_FUNCTIONS="1"
$env:ONBOARD_LOG_VALUE_LIMIT="4000"
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload

For the extremely noisy maximum Python call trace, also run this before Uvicorn:

$env:ONBOARD_MAX_TRACE="1"

TOGGLE MODEL PROVIDER / ARCHITECTURE FOR TESTING
-------------------------------------------------

# These use $env:VAR overrides scoped to ONE PowerShell terminal session only -
# they never touch the real .env file. Close and reopen the terminal (or run
# the "restore" block) to go back to normal. Restart the backend after any
# change here - settings load once at process start.

# --- Force Bedrock ONLY (hide the Anthropic API key + Claude Code fallback
#     for this terminal, so the cascade can't fall through past Bedrock) ---
$env:ANTHROPIC_API_KEY=""
$env:WAYPOINT_CLAUDE_CODE_FALLBACK="0"
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload

# --- Force the direct Anthropic API ONLY (hide the AWS region for this
#     terminal so Bedrock is never attempted) ---
$env:AWS_REGION=""
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload

# --- Force the Claude Code subscription fallback ONLY (hide both Bedrock and
#     the Anthropic API key; requires `claude login` already completed once) ---
$env:AWS_REGION=""
$env:ANTHROPIC_API_KEY=""
$env:WAYPOINT_CLAUDE_CODE_FALLBACK="1"
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload

# --- Restore normal cascade (Bedrock -> Anthropic API -> Bedrock retry ->
#     Claude Code) in the current terminal ---
$env:AWS_REGION="us-east-1"
$env:ANTHROPIC_API_KEY=$null
Remove-Item Env:\ANTHROPIC_API_KEY -ErrorAction SilentlyContinue
$env:WAYPOINT_CLAUDE_CODE_FALLBACK="1"
# (ANTHROPIC_API_KEY then reloads from .env on the next backend start, since
# only the current shell's override was cleared, not the file itself.)

# --- Toggle single-model vs dual-role (investigation/synthesis split) ---
# Edit .env directly for a persistent change (restart backend after editing):
#   WAYPOINT_MODEL_ARCHITECTURE=single    <- one model handles the whole conversation
#   WAYPOINT_MODEL_ARCHITECTURE=dual      <- Sonnet investigates, Opus synthesizes (current default)

# --- Confirm which provider/model actually served the last request ---
# Check the trace log's most recent model.role_routed / model.response_received
# events, or hit the usage endpoint for the routed_provider on real ledger rows:
curl.exe -s http://127.0.0.1:8000/api/v1/usage/summary
